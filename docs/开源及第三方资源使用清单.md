# 开源及第三方资源使用清单

> 参赛材料必交附件（对应赛题「作品要求（五）」）。
> **本文件随开发持续更新**；每一项都必须能在代码里找到出处，不得事后补写。
>
> 自检方式：本文件里出现的每一个文件路径，都应该能在仓库里打开；每一个版本号，
> 都应该能用 `pip show` 复现；每一个行数（`wc -l`）与测试条数（`python -m pytest`）
> 都是**实测**，不是估的。

本作品是一个 **fork**：交付本体是上游 MiroFish 的一个衍生仓库，
新增的是 `backend/verification/` —— 一组运行时守卫与离线复现。
**本清单先把「哪些是上游的、哪些是我们的」分开**，因为这是本作品最容易被误读的地方。

在上游基础上**改动或新增**的部分（描述的是「改了哪一部分」，不是「关系有多浅」）：

- 上游 `chat_agent.update_memory` 的**切片行为** —— 不改上游源码，而是**在运行时**由
  `camel_guards` 打补丁包住它（默认关闭）。装置不声称「修好了上游」，
  只声称「**这一次跑的产出可不可信**」这个问题被变成可判定的。
- 上游的**时间戳推进**（`base_timestamp + 1e-6`）—— 同上，运行时包住，默认关闭。
- 上游的 **Zep Cloud 记忆** —— 装置**不碰**：三条复现与端到端那一跑用的是本地
  SQLite 写入路径，所以整套装置**不需要 Zep 账号、不需要 API key**。
- 上游**并发次序**那一层 —— **不修**，只核实与测量，并写成边界。

> **一处刻意的设计：报告不解析数字，只做原样转录。** 装置报的每一个数，都是那条命令
> **当时打在屏幕上的原话**逐字抄下来的，不重算。理由：一旦报告里的数字是「再算一遍」
> 得来的，它和产生它的那次运行就可能对不上 —— 而这份报告的全部意义就是
> 「**我看到的和它说的是同一件事**」。
